4 执行数据迁移

⚠️ 注意

下面的 SQL 会将现有 users 表中的管理员数据迁移到新的 admin_users 和 admin_positions 表。

确保你已经执行过 admin_system.sql 创建了新表。

4.1 迁移管理员账户

-- 迁移管理员账户到 admin_users INSERT INTO admin_users ( id, username, password_hash, real_name, phone, email, identity_label, identity_suffix, identity_suffix_status, status, created_by, created_at, updated_at ) SELECT u.id, u.username, u.password_hash, COALESCE(u.real_name, u.username) as real_name, u.phone, NULL as email, CASE WHEN u.username LIKE '%超级管理员%' THEN '运营专员' WHEN u.username LIKE '%学校管理员%' THEN '教职工' ELSE '工作人员' END as identity_label, NULL as identity_suffix, 'draft' as identity_suffix_status, CASE WHEN u.status = 'active' THEN 'active' ELSE 'disabled' END as status, NULL as created_by, u.created_at, u.updated_at FROM users u WHERE u.role = 'admin' ON DUPLICATE KEY UPDATE real_name = VALUES(real_name), identity_label = VALUES(identity_label), updated_at = NOW();

4.2 迁移管理员职位

📝 重要说明

你的 users 表没有 school_id/merchant_id/stall_id 字段，所以下面仅创建职位与角色，节点绑定后续在管理员界面手动分配。

-- 迁移管理员职位（不绑定节点，后续在后台手动分配） INSERT INTO admin_positions ( admin_id, role, assigned_by, assigned_at ) SELECT u.id as admin_id, CASE WHEN u.username LIKE '%超级管理员%' THEN 'super_admin' WHEN u.username LIKE '%学校管理员%' THEN 'school_admin' WHEN u.username LIKE '%商户管理员%' THEN 'merchant_admin' WHEN u.username LIKE '%档口管理员%' THEN 'stall_admin' ELSE 'school_admin' END as role, COALESCE( (SELECT id FROM admin_users WHERE username = '超级管理员' LIMIT 1), (SELECT id FROM admin_users ORDER BY id LIMIT 1) ) as assigned_by, u.created_at as assigned_at FROM users u WHERE u.role = 'admin' ON DUPLICATE KEY UPDATE assigned_at = VALUES(assigned_at);

4.3 分配默认权限

-- 为每个职位分配默认权限 INSERT INTO admin_permissions ( position_id, permission, granted_by, granted_at ) SELECT ap.id as position_id, rtp.permission, 1 as granted_by, NOW() as granted_at FROM admin_positions ap JOIN role_template_permissions rtp ON rtp.role = ap.role AND rtp.is_default = TRUE WHERE NOT EXISTS ( SELECT 1 FROM admin_permissions WHERE position_id = ap.id AND permission = rtp.permission );

5 验证迁移结果

📍 执行验证 SQL

-- 检查迁移后的数据 SELECT '原 users 表管理员' as 类型, COUNT(*) as 数量 FROM users WHERE role = 'admin' UNION ALL SELECT '新 admin_users 表' as 类型, COUNT(*) as 数量 FROM admin_users UNION ALL SELECT '新 admin_positions 表' as 类型, COUNT(*) as 数量 FROM admin_positions UNION ALL SELECT '已分配权限' as 类型, COUNT(*) as 数量 FROM admin_permissions WHERE revoked_at IS NULL;

✅ 对比数量

原 users 表管理员数量应该等于新 admin_users 表的数量。

如果数字匹配，说明迁移成功！

查看具体数据

-- 查看迁移后的管理员 SELECT au.id, au.username, au.real_name, au.identity_label, au.status, COUNT(ap.id) as position_count FROM admin_users au LEFT JOIN admin_positions ap ON ap.admin_id = au.id AND ap.unassigned_at IS NULL GROUP BY au.id ORDER BY au.id;

6 禁止注册管理员

⚠️ 重要安全措施

现在注册接口还可以直接注册管理员，这是严重的安全隐患！

我们需要通过两种方式修复：

  1. 数据库层面：添加触发器防止插入管理员
  2. 代码层面：后端强制检查（已修复）

6.1 添加数据库触发器

-- 创建触发器防止注册管理员 DELIMITER $$ DROP TRIGGER IF EXISTS prevent_admin_registration$$ CREATE TRIGGER prevent_admin_registration BEFORE INSERT ON users FOR EACH ROW BEGIN IF NEW.role = 'admin' THEN SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = '禁止通过注册接口创建管理员账户'; END IF; END$$ DELIMITER ;

6.2 验证触发器

-- 验证触发器是否创建成功 SELECT TRIGGER_NAME, EVENT_MANIPULATION, EVENT_OBJECT_TABLE, ACTION_TIMING FROM information_schema.TRIGGERS WHERE TRIGGER_SCHEMA = DATABASE() AND TRIGGER_NAME = 'prevent_admin_registration';

✅ 后端代码已修复

文件 backend/controllers/authController.js 已更新。

现在即使前端传入 isAdmin=true，后端也会返回 403 错误。

6.3 标记已迁移的用户

-- 为 users 表添加迁移标记字段 ALTER TABLE users ADD COLUMN IF NOT EXISTS migrated_to_admin_system BOOLEAN DEFAULT FALSE; -- 标记已迁移的管理员 UPDATE users SET migrated_to_admin_system = TRUE WHERE role = 'admin';

🆘 常见问题排查

问题 1：迁移后数量不匹配

原因：可能有些管理员在 users 表中没有正确的 role 标记。

解决：手动查看 users 表，找出漏掉的管理员并手动迁移。

问题 2：职位关联字段不存在

原因：你的 users 表可能没有 school_id/merchant_id/stall_id 字段。

解决：跳过步骤 4.2，改为在管理员界面手动分配职位。

问题 3：管理员登录后没有权限

原因：可能没有执行步骤 4.3 分配默认权限。

解决：重新执行步骤 4.3 的 SQL。

问题 4：注册接口还是能创建管理员

原因：后端代码没有更新或触发器创建失败。

解决：检查 authController.js 是否已更新，重启后端服务。

问题 5：触发器创建失败

原因：phpMyAdmin 不支持 DELIMITER 语法。

解决：改用宝塔命令行：

mysql -u root -p数据库名 < fix_registration.sql
